# Умный кредитный кабинет предпринимателя

Прототип цифрового кредитного конвейера для малого и среднего бизнеса. Предприниматель в веб-кабинете
добавляет свою компанию, видит, сколько ему могут дать, подаёт заявку и в реальном времени следит, где она.
Банк за несколько секунд собирает данные из (смоделированных) внешних источников, проверяет стоп-факторы,
считает скоринговый балл и лимит по доходу и возвращает понятное решение: одобрение, контрпредложение
с вариантами или отказ с причинами и советом, что делать дальше. Подписание — имитация кода из SMS.
Все данные синтетические, все внешние сервисы смоделированы, приложение работает автономно.

**Версия:** тег `vX`, commit `<hash>`

**Демо:** http://213.176.77.81

## Что умеет

**Клиент**
- Регистрация и вход; добавление компании по ИНН — только своей (руководитель в ЕГРЮЛ = пользователь).
- Карточка компании: реквизиты, МСП, налоги, ФССП, банкротства, ЗСК, кредиты, обороты по месяцам с прогнозом;
  сводка по группе компаний одного владельца; предварительный лимит до подачи заявки.
- Заявка в несколько шагов с автозаполнением; таймлайн статусов в реальном времени.
- Решение простыми словами: одобрение; контрпредложение — меньшая сумма на тот же срок или вся сумма
  на срок длиннее; мягкий отказ с датой повторной подачи; отказ или ручной разбор — всегда с причинами и советом.
- Выбор варианта, подписание кодом, выдача; отказ от кредита до подписания.

**Конвейер банка**
- Очередь заявок в PostgreSQL и воркер: сбор данных из 8 источников → стоп-факторы → признаки → скоринг →
  лимит по DSCR → решение и варианты.
- Сбой источника — повторы, затем ручной разбор (не ошибка клиенту). Повторная отправка не создаёт дубль.

**Скоринг**
- Скоркарты (WoE + логистическая регрессия) на синтетике из 40 тыс. заявок, модель выбирается по сегменту
  компании, грейды A–E. Подробно — [docs/model-card.md](docs/model-card.md); как пересобрать синтетику
  и модели — [ml/README.md](ml/README.md).

**Кабинет администратора** (`/adminuser`)
- Все компании (синтетика и клиенты) с разложением балла по признакам, стоп-факторами, кредитной историей,
  пересчётом; модели, бины и калькулятор; выборки «решение × факт», champion / challenger, стабильность.

## Архитектура

```
браузер → frontend (React + nginx) → app (FastAPI) → PostgreSQL ← worker (конвейер)
                                         └──────── HTTP ────────→ simulator (ЕГРЮЛ, ФНС, РМСП, ФССП,
                                                                   ЕФРСБ, ЗСК, БКИ, АБС банка)
```

## Запуск локально

**Нужно:** Docker Desktop (или Docker Engine + Compose v2), ~2,5 ГБ свободного места (образы ~1,6 ГБ + сборка и база), свободные порты
5500, 8000, 8100, 5432. Больше ничего ставить не нужно — ключи, `.env` и доступ в интернет к внешним
сервисам не требуются (только для скачивания образов при первой сборке).

```bash
git clone https://github.com/harumaw/credit_risk.git
cd credit_risk
docker compose up -d --build --wait
```

Первый старт — несколько минут: сборка образов, затем app сам применяет миграции, создаёт демо-учётки,
загружает модели скоринга и 10 000 синтетических компаний (на обычном ноутбуке — около минуты).
`--wait` вернёт управление, когда все сервисы будут здоровы. Повторный `up` синтетику заново не грузит
и стартует за секунды.

| Адрес | Что там |
|---|---|
| http://localhost:5500 | кабинет клиента (начните отсюда) |
| http://localhost:5500/adminuser | кабинет администратора: логин `ovv`, пароль `1234567890@` |
| http://localhost:8000/docs | OpenAPI (Swagger) — все методы API |
| http://localhost:8100/docs | симулятор внешних источников |

```bash
docker compose ps              # состояние сервисов
docker compose logs -f app     # логи (app, worker, simulator, frontend, postgres)
docker compose down            # остановить, данные сохранятся
docker compose down -v         # остановить и удалить базу — следующий up начнёт с нуля
```

**Порт занят.** Порты на машине задаются переменными — например, если 5432 занят другим Postgres:

```bash
POSTGRES_PORT=5433 docker compose up -d --build --wait
```

Переменные: `FRONTEND_PORT` (5500), `APP_PORT` (8000), `SIMULATOR_PORT` (8100), `POSTGRES_PORT` (5432).
Их можно положить в файл `.env` рядом с `docker-compose.yml`.

## Проверка за 2 минуты

Два способа: зарегистрироваться самому и добавить тестовую компанию (А) или войти демо-учёткой
и добавить её собственную компанию (Б). Работает и локально, и на демо-сервере.

> **Почему нельзя добавить любую компанию.** Зарегистрироваться можно с любым корректным ИНН физлица
> (проверяется контрольная сумма, ИНН не должен быть занят) — готовые ИНН ниже. А вот компанию в кабинет
> можно добавить, только если вы её руководитель по ЕГРЮЛ: так чужой человек не увидит данные и не подаст
> заявку от чужой компании (иначе — отказ 403). Для произвольного ИНН компании симулятор реестра придумывает
> руководителя, и он с вами не совпадёт. Поэтому новому пользователю доступны 6 тестовых ИНН `99000000xx` —
> для них симулятор записывает руководителем того, кто добавляет компанию, — или демо-учётки с готовыми
> компаниями (способ Б, пароль `demo12345`).

1. Зарегистрируйтесь: любые ФИО, email, пароль и ИНН физлица из списка ниже. ИНН у пользователей
   не повторяется — возьмите тот, что ещё никто не занял:

   <!-- registration-inns -->
   `771234560162` `771234560236` `771234560300` `771234560483` `771234560557`
   `771234560620` `771234560701` `771234560878` `771234560941` `771234561046`

3. Подайте заявку (например, 1 млн на 12 мес — для «контрпредложения» возьмите 5 млн) — через
   несколько секунд придёт решение, статусы обновляются сами.

| ИНН | Компания | Что будет |
|---|---|---|
| 9900000017 | ООО «Тест — одобрение» | одобрение (грейд A, долгов нет) |
| 9900000024 | ООО «Тест — контрпредложение» | на выбор: меньшая сумма на тот же срок или вся сумма на срок длиннее |
| 9900000031 | ООО «Тест — мягкий отказ» | отказ: бизнесу 4 месяца, дата, когда подать снова |
| 9900000049 | ООО «Тест — ручной разбор» | ручной разбор: просрочка 45 дней в прошлом |
| 9900000056 | ООО «Тест — банкротство» | отказ без скоринга: процедура банкротства |
| 9900000063 | ООО «Тест — нужна выписка» | ручной разбор: оборотов в нашем банке нет, нужна выписка |

Эти ИНН может добавить любой пользователь; заявки по ним видит только их автор. Проверка защиты:
ИНН `7701234560` («Северный ветер») новому пользователю добавить нельзя — будет «Руководитель в реестре —
другой человек»: так и должно быть.

4. После одобрения примите условия (при контрпредложении — выберите вариант), запросите код и введите
   его — код показывается на экране вместо SMS. Статус сменится на «Кредит выдан».

## Как принимается решение

| Ситуация | Исход | Почему |
|---|---|---|
| ИП Игоря, 1 млн / 12 мес | одобрено | грейд A, долгов нет |
| «Северный ветер», 5 млн / 12 мес | контрпредложение: ≈2,7 млн / 12 мес или 5 млн / 36 мес | платёж по запросу не помещается в доход (нужен DSCR ≥ 1,25) |
| «Новый старт» | мягкий отказ + дата, когда подать снова | бизнесу меньше 6 месяцев |
| «Вектор» | ручной разбор | просрочка 45 дней в прошлом |
| «Закат» | отказ без скоринга | банкротство — жёсткий стоп-фактор |
| ИП Анны | ручной разбор | оборотов в нашем банке нет — нужна выписка |

Матрица: грейд A–B — одобрение или контрпредложение в пределах лимита по доходу; C — ручной разбор;
D–E — отказ. Предложение никогда не превышает того, что позволяет доход. Решение хранит версию модели,
входные данные, баллы по признакам и коды причин. Подробно — [docs/architecture.md](docs/architecture.md#решение-по-заявке).

## Модель скоринга

- **Модель при запуске не обучается.** Готовые скоркарты лежат в `ml/artifacts/models.json` и загружаются
  в базу автоматически при старте app; там же хранятся правила, какую модель к какой компании применять.
- **Данные для обучения** — синтетика из 40 тыс. заявок 2023–2025: кредитные истории из соревновательного
  датасета scoring_maps (помесячные статусы платежей) плюс сгенерированный бизнес-профиль компании (реестры,
  обороты, налоги, ФССП, ЗСК). Целевая метка — дефолт в течение 12 месяцев.
- **Что в репозитории:** готовые файлы синтетики `ml/data/synthetic_v1/` (компании, кредиты, обороты, витрина
  признаков, разметка выборок), ноутбук исследования `ml/research.ipynb`, библиотека скоркарт
  `ml/scorecard_lib.py`, итоговые модели `ml/artifacts/models.json`.
- **Переобучить** (по желанию): ноутбук читает только файлы из `ml/data/synthetic_v1/`, его можно перезапустить —
  он заново построит модели и перезапишет `models.json`; как — в [ml/README.md](ml/README.md).
- Метрики, признаки, ограничения — [docs/model-card.md](docs/model-card.md).

## Тесты

Автотесты (pytest, около 150) идут на настоящем PostgreSQL 16. Нужны Python 3.12 и Poetry:

```bash
docker compose up -d postgres
poetry install
poetry run pytest
```

- Тестовая база `TEST_DATABASE_URL` (по умолчанию `postgresql+asyncpg://app:secret@localhost:5432/app_test`)
  на каждый прогон создаётся заново и поднимается миграциями — прогон заодно проверяет миграции.
  Рабочую базу `app_db` тесты не трогают. Если Postgres на другом порту — поменяйте порт в `TEST_DATABASE_URL`.
- Каждый тест — в транзакции с откатом; тесты одновременной отправки заявок работают на отдельных
  соединениях и убирают за собой.
- Что покрыто: правила решения и стоп-факторы, лимит, признаки и скоркарта (паритет с обучающей выборкой —
  `tests/api/test_scoring_parity.py`), конвейер для всех персон, статусы и 409, подписание,
  идемпотентность и гонки, доступ к чужим данным, симулятор и интеграции, загрузка синтетики.
- Линтер: `poetry run ruff check` и `poetry run ruff format --check`; фронт: `cd frontend && npm ci && npm run build`.

Сценарии ручной проверки — [docs/test-scenarios.md](docs/test-scenarios.md).

## Упрощения

- **Выписка из другого банка и бухгалтерская отчётность (ГИР БО)** не загружаются: если оборотов в нашем
  банке нет, заявка уходит на ручной разбор с причиной «нужна выписка».
- **Недостоверность сведений ЕГРЮЛ и массовость** (адрес, руководитель) как стоп-факторы не проверяются.
- **SMS не отправляется:** код подписи показывается в интерфейсе (живёт 5 минут, 5 попыток).
- **Внешние источники смоделированы** симулятором; для тестовых ИНН `99…` он записывает руководителем
  того, кто спрашивает, — реальный реестр так не делает.
- **Данные синтетические:** метрики моделей не переносятся на реальный портфель — см. model card.
- **Пересборка датасета с нуля** (`ml/synth/build_dataset.py`) требует внешний исходник кредитных историй
  (соревновательный датасет scoring_maps), которого нет в репозитории. Готовая синтетика и модели в репозитории
  есть, переобучение моделей на ней работает без него.
