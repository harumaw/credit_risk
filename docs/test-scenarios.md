# Сценарии проверки

Как пройти продукт руками через интерфейс и какие автотесты покрывают то же самое.
Все данные синтетические, внешние источники отвечают из локального симулятора.

## Подготовка

```bash
docker compose up -d --build
```

Через минуту откройте <http://localhost:5500>. Схема API — <http://localhost:8000/docs>,
коллекция запросов — [`api-collection.postman.json`](api-collection.postman.json).

Цифры ниже получены на чистом стенде: сумма и срок по умолчанию, продукт «Кредит на оборотные средства».
Решение приходит через 2–5 секунд. Страницу обновлять не нужно, статус меняется сам (SSE).

## 1. Регистрация и вход

| Шаг | Что сделать | Что видно |
|---|---|---|
| 1 | «Войти» → «Регистрация». Заполнить фамилию, имя, email, пароль от 8 символов, ИНН физлица из списка в README (например `771234560162`) | Обязательные поля отмечены красной точкой |
| 2 | Ввести ИНН с ошибкой в контрольной сумме, например `771234560163` | У поля ИНН: «Контрольные цифры не сходятся — проверьте ИНН» |
| 3 | Исправить ИНН и отправить | Кабинет «Здравствуйте, <имя>» с кнопкой «Добавить компанию» |
| 4 | Зарегистрироваться ещё раз с тем же email или ИНН | «Пользователь с таким … уже зарегистрирован» |
| 5 | Выйти и войти снова с неверным паролем | «Неверный email или пароль» |

## 2. Тестовые компании (песочница)

Эти 6 ИНН может добавить любой пользователь: симулятор ЕГРЮЛ запишет руководителем того, кто их добавляет.
Остальные данные копируют профиль одной из демо-персон, поэтому исход заранее известен.
Заявки по тестовой компании видит только их автор.

Путь для каждой строки: «Добавить компанию» → ИНН → «Найти» → «Да, добавить» → данные собираются из 8 источников →
карточка компании → «Подать заявку» → сумма и срок из таблицы → два согласия → «Отправить заявку».

| ИНН | Заявка | Исход | Что видно на экране |
|---|---|---|---|
| `9900000017` | 1 млн / 12 мес | **Одобрено**, рейтинг A | Таймлайн: «Заявка отправлена → Оцениваем заявку → Одобрено». Баннер «Одобрено: 1 000 000 ₽ на 12 мес» → «Посмотреть решение»: один вариант, 24 %, платёж 94 560 ₽ в месяц |
| `9900000024` | 5 млн / 12 мес | **Контрпредложение**, рейтинг B | «Есть решение: можем дать 2 735 000 ₽ на 12 мес». На странице решения два варианта: «Тот же срок, сумма меньше» (2 735 000 ₽ / 12 мес, платёж 259 946 ₽) и «Вся сумма, срок длиннее» (5 000 000 ₽ / 36 мес, платёж 198 799 ₽), ставка 25 %. Причина: «Запрошенная сумма больше, чем позволяет доход компании» |
| `9900000031` | 500 тыс / 12 мес | **Мягкий отказ** | «Эту сумму сейчас дать не можем». Причина: «Бизнесу меньше 6 месяцев», рейтинг A. Справа «Что поможет в следующий раз: подайте заявку после <дата> — бизнесу исполнится 6 месяцев» |
| `9900000049` | 3 млн / 12 мес | **Ручной разбор** | Статус «Проверяем», баннер «Заявку смотрит специалист». Причина: «В кредитной истории была просрочка больше 30 дней» |
| `9900000056` | любая, например 1 млн / 12 мес | **Отказ без скоринга** (стоп-фактор) | В карточке компании нет предварительного лимита. Отказ с причинами «Компания не действует по данным реестра» и «По компании есть сообщения о банкротстве», рейтинга нет |
| `9900000063` | 500 тыс / 12 мес | **Ручной разбор**: нужна выписка | В карточке компании нет лимита: оборотов в нашем банке нет. Заявка у специалиста с причиной «Нет оборотов по счёту в нашем банке» |

Проверки по ходу:

- **Чужая компания.** ИНН `7701234560` («Северный ветер», руководитель — демо-персона) новому пользователю добавить нельзя.
  После «Найти» появится «Руководитель — другой человек. Добавить компанию нельзя».
- **Повтор.** Та же тестовая компания второй раз: «Эта компания уже в вашем кабинете» и кнопка «Открыть компанию».
- **Неверный ИНН компании**, например `1234567890`: ошибка контрольной суммы, запрос в реестр не уходит.

## 3. Демо-учётки

Создаются при старте автоматически, пароль у всех `demo12345`. В каждой учётке компанию сначала нужно добавить:
«Добавить компанию» → ИНН из таблицы.

| Email | ИНН компании | Заявка | Исход |
|---|---|---|---|
| igor@example.com | `770700000190` (ИП) | 1 млн / 12 мес | одобрение |
| anna@example.com | `7701234560` | 5 млн / 12 мес | контрпредложение: 2 735 000 ₽ / 12 мес или 5 млн / 36 мес |
| anna@example.com | `500100000015` (ИП) | 500 тыс / 12 мес | ручной разбор: нужна выписка из другого банка |
| olga@example.com | `7801002002` | 500 тыс / 12 мес | мягкий отказ: бизнесу 4 месяца |
| dmitry@example.com | `5403004007` | 3 млн / 12 мес | ручной разбор: просрочка 45 дней в прошлом |
| sergey@example.com | `6605006009` | любая | отказ без скоринга: банкротство |

**Группа компаний.** У anna@example.com добавьте все три компании: `7701234560`, `500100000015`, `7705551232`.
На странице `/cabinet/companies` появится сводка по группе. Лимит каждой компании считается с учётом долгов всей группы.

## 4. Контрпредложение → выбор варианта → код → выдан

Компания `9900000024` или anna@example.com с `7701234560`, заявка 5 млн / 12 мес.

1. Баннер «Есть решение…» → «Посмотреть решение».
2. Выбрать вариант «Вся сумма, срок длиннее» (5 000 000 ₽ / 36 мес) → «Принять и перейти к подписанию».
   Статус меняется на «Подписание».
3. «Получить код». Появится поле для 6 цифр и плашка «Демо: в банке код придёт по SMS» с кодом.
4. Ввести код → «Подписать». Экран «Деньги на счёте», статус «Выдан».
5. Открыть заявку. В таймлайне: отправлена → оцениваем → предложены другие условия → подписание → выдан.
   Отозвать выданную заявку нельзя.

**Повторная отправка.** Двойной клик по «Отправить заявку» или повтор после сбоя сети не создаёт вторую заявку:
форма шлёт один и тот же `Idempotency-Key`.

## 5. Отказ клиента

- **На подписании.** Дойти до шага 3 сценария 4 → «Отказаться от кредита» → «Да, отказаться».
  Статус «Отменена», в таймлайне «Заявка отменена — Клиент отказался от кредита». Принять условия снова нельзя.
- **На решении.** На странице решения «Отказаться» → подтверждение. Итог тот же.
- **До решения.** Сразу после отправки на странице заявки «Отозвать заявку» → «Да, отозвать». Баннер «Заявка отозвана»,
  решение по ней не выносится.

## 6. Неверный код 5 раз

1. Дойти до шага 3 сценария 4.
2. Ввести 4 раза неверный код, например `000000`. Каждый раз: «Неверный код».
3. Пятый неверный ввод: «Код введён неверно 5 раз и больше не действует — запросите новый».
4. Ввести прежний верный код. Он уже не принимается: «Сначала запросите код».
5. «Получить код» ещё раз, ввести новый код. Договор подписан, статус «Выдан».

Код действует ограниченное время, просроченный не принимается.

## 7. Кабинет администратора `/adminuser`

1. Открыть <http://localhost:5500/adminuser>. Вход для сотрудника отдельный: логин `ovv`, пароль `1234567890@`
   (в dev-compose по умолчанию, переменные `ADMIN_LOGIN` / `ADMIN_PASSWORD`).
2. **Компании.** Сводка (сколько компаний, оценено, одобрено, отказов) и таблица с фильтрами по грейду, решению, факту
   дефолта и источнику. Фильтр «Источник → клиенты кабинета» оставит компании из сценариев 2–4. Таблицу можно выгрузить в CSV.
3. **Карточка компании.** Разложение балла по признакам, стоп-факторы, кредитная история и обороты, история скорингов.
   «Пересчитать» считает балл заново по уже собранным данным, без новых запросов к источникам.
4. **Модели.** Скоркарты: бины, баллы, мастер-шкала, калькулятор, правила выбора модели по сегменту.
5. **Выборки и узкие места.** Решение × факт, пропуски модели, упущенные клиенты, champion / challenger,
   стабильность по месяцам. Нужна обучающая выборка:
   `docker compose exec app python -m app.dataload.synthetic --limit 10000`.
   Без неё в разделе видны только клиенты кабинета.
6. Клиентский токен в кабинете администратора не работает, токен сотрудника — в клиентском API тоже.
